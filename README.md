# microart2mqtt

Показания инверторов **МикроАрт** в **MQTT**.

Агент ставится на саму «Малину» инвертора, читает её локальный API и публикует
в брокер **всё, что устройство отдаёт** — топики создаются сами, описывать поля
не нужно. Настройка и обновление — в браузере.

```
«Малина» inv1 ── malina-agent ──MQTT──>  ┌────────┐
«Малина» inv2 ── malina-agent ──MQTT──>  │ брокер │ ──>  умный дом, Grafana, бот
«Малина» inv3 ── malina-agent ──MQTT──>  └────────┘
```

Агенты между собой не связаны: каждый подключается к брокеру **своим
соединением**, со своим `client_id`, и пишет в **свои** топики
(`microart/inv1/…`, `microart/inv2/…`). Ничего общего и никакого узла-посредника
— упал один инвертор, остальные продолжают публиковать. Дальше показания
забирает любой подписчик.

В репозитории две программы:

| | |
|---|---|
| **`cmd/malina-agent`** | агент на устройстве. Основной путь |
| `cmd/microart2mqtt` | центральный демон: опрашивает «Малины» по сети с отдельного сервера, если прошивку трогать не хочется |

## Что публикуется

```
microart/inv1/map/_UNET            231.0
microart/inv1/map/_PLoad           820
microart/inv1/bat/0/C_100_remain   88.0      ← minute_data
microart/inv1/bat/1/Sun_P          1450      ← second_data
microart/inv1/mppt/0/P_PV          1450
microart/inv1/map                  {…весь JSON раздела…}
microart/inv1/availability         online | offline
```

Имена полей — как в API «Малины»; разделы `map`, `bat`, `mppt` соответствуют
запросам `read_json.php?device=…`. Корень (`microart/inv1`) задаётся в вебе, у
каждого инвертора свой.

В брокер уходят **только изменившиеся** значения; раз в `republish_sec`
(по умолчанию 10 минут) — весь набор заново, на случай если подписчик или
брокер потеряли состояние. Всё с `retain`.

Полное описание топиков, значений, таблица частых полей и примеры подписки —
в **[TOPICS.md](TOPICS.md)**.

## Установка на «Малину»

Одна команда собирает готовый к прошивке образ: агент, установщик и юнит
кладутся **прямо в `/boot`**, копировать на карту руками ничего не нужно.

```sh
make image IMAGE=путь/к/образу.img
```

Исходный образ не меняется — правки идут в копию `..._mqtt-mod.img`, её и пишем
на карту:

```sh
diskutil list external physical           # найти карту (сверьте размер!)
diskutil unmountDisk /dev/diskN
sudo dd if=путь/к/образу_mqtt-mod.img of=/dev/rdiskN bs=4m
sudo diskutil eject /dev/diskN
```

Карту в «Малину», включить, подождать ~2 минуты. Агент ставится **сам**:

- службой systemd (`microart-mqtt.service`, `Restart=always`);
- проксируется через их nginx на `http://<ip>/mqtt/`;
- в меню веб-морды появляется кнопка **MQTT**.

Затем в браузере: `http://<ip>/mqtt/` → адрес брокера → свой корень топиков
(`microart/inv1`, `inv2`, …) → галочка «Агент включён» → **Сохранить**.

Установка идемпотентна: повторная прошивка или перезагрузка ничего не ломает.

### Несколько устройств

Образ **общий** для всех — различается только `base_topic`, который задаётся
в вебе каждого устройства. Отдельный образ на инвертор делать не нужно.

Если устройство уже настроено и терять его калибровку нельзя, полную прошивку
лучше не делать: снимите карту и пропатчьте её на месте — `/settings` (калибровка
батарейного монитора, сеть, история) останется нетронутым.

```sh
python3 tools/malina_bootstrap.py /dev/rdiskN --apply
python3 tools/fat_put.py /dev/rdiskN MICROART \
    exe/microart-boot/malina-agent=AGENT \
    deploy/malina/agent-ctl.sh=AGENTCTL.SH \
    deploy/malina/install-on-malina.sh=INSTALL.SH \
    deploy/malina/microart-mqtt.service=AGENT.SRV
```

### Обновление

Кнопкой **«Обновить»** на странице агента: он качает свежий бинарник из релиза
GitHub, сверяет SHA256, проверяет, что тот запускается, заменяет себя и
перезапускается. Прежняя версия сохраняется рядом для отката.

Веб-интерфейс лежит внутри бинарника — обновляется вместе с агентом.

### Диагностика

Оба лога открываются в браузере, без консоли и снятия карты:

```
http://<ip>/mqtt-install.txt    как прошла установка
http://<ip>/mqtt-agent.txt      лог агента
```

На устройстве: `systemctl status microart-mqtt`. Консоль на мониторе — автологин
`pi` (вписывается в образ тем же `malina_bootstrap.py`).

## Что агент делает сам

**Шлёт только изменения.** Если публикация не прошла, значение **не** считается
отправленным и уйдёт в следующем цикле: иначе топик остался бы пустым до
планового рефреша.

**Переживает недоступный брокер.** Стартует, даже если брокера ещё нет, и
переподключается сам.

**Не публикует пустоту.** Поля, которых «Малина» не прислала для своей
конфигурации, пропускаются: пустое значение в ретейн-топике хуже прежнего.

**Отмечает доступность.** `availability` = `online`/`offline`, плюс завещание
(LWT) на случай внезапной пропажи связи. При штатной остановке и выключении в
вебе `offline` выставляется явно.

**Частота опроса** — по умолчанию 5 секунд, минимум 1. Чаще смысла нет: сама
«Малина» усредняет данные с шагом 5 секунд, `second_data` обновляется раз в
секунду, `minute_data` — раз в минуту.

## Центральный демон (альтернатива)

Если на устройства ставить ничего не хочется — `cmd/microart2mqtt` опрашивает
«Малины» по сети с отдельного сервера. Инверторы, метрики и брокер задаются в
его собственном веб-интерфейсе, настройки хранятся в SQLite.

```sh
curl -fsSL https://github.com/staskuznec/microart2mqtt/releases/latest/download/install.sh | sudo sh
```

Установщик скачает бинарник под вашу архитектуру, сверит сумму, заведёт службу
systemd и при желании откроет управление рядом с существующей панелью
(`http://сервер/microart/`). Настройки лежат отдельно, в
`/var/lib/microart2mqtt`, и при обновлении не трогаются.

Отличие от агента: метрики здесь задаются списком (можно выбрать поля из живого
API, взять готовый набор или скопировать с соседнего инвертора), опрос идёт по
сети, поэтому чаще 5 секунд ходить не стоит — каждый запрос поднимает PHP.

## Устройство проекта

```
cmd/malina-agent/    агент на «Малине»: опрос, публикация, свой веб, обновление
cmd/microart2mqtt/   центральный демон
internal/
  microart/          HTTP-клиент «Малины» и разбор ответов API (общий)
  mqtt/              клиент брокера: подключение с LWT, публикация, топики
  poller/            опрос одного инвертора и фильтр изменений
  store/             SQLite центрального демона: настройки, инверторы, метрики
  web/               веб-интерфейс центрального демона
  app/               связывает хранилище, брокер и опрос
  update/            проверка новой версии
  logging/           журнал: stdout плюс кольцевой буфер для страницы
deploy/malina/       всё для устройства: юнит systemd, установщик, agent-ctl
tools/               работа с образом прошивки без монтирования
```

Инструменты в `tools/` — потому что macOS не умеет ext4, а выкусывать файлы
поиском по байтам ненадёжно:

| | |
|---|---|
| `ext4extract.py` | чтение файлов из ext4: суперблок, экстенты, каталоги, разделы из MBR |
| `fat_put.py` | запись файлов в FAT32-раздел `/boot` (проверено `fsck_msdos`) |
| `malina_bootstrap.py` | вписать в образ автозапуск агента и консольный вход |

Прошивка «Малины», вытащенные из неё файлы МикроАрт и каталог сборки в
репозиторий не входят — это чужой код и большие бинарники, им место локально.

CGO не нужен: агент без зависимостей, SQLite взят чистый на Go
(`modernc.org/sqlite`), поэтому сборка под ARMv7 ничем не отличается от сборки
под хост.

### Разработка

```sh
make agent          # собрать агента под текущую платформу
make agent-armv7    # собрать агента под «Малину»
make image          # готовый к прошивке образ
make test           # gofmt, go vet, go test -race, проверка скриптов
make run            # локальный запуск центрального демона
```

### Релизы

Сборка по тегу `v*`: GitHub Actions гоняет проверки, собирает обе программы под
три архитектуры, считает контрольные суммы и прикладывает к релизу бинарники,
`SHA256SUMS`, установщики и юниты. По `SHA256SUMS` сверяет себя самообновление
агента. Описание релиза берётся из сообщения тега.

```sh
git tag -a v0.1.0 -m "Что и зачем изменилось"
git push origin v0.1.0
```
