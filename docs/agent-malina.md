# Агент на «Малине»: как устроено устройство

Заметки по прошивке МикроАрт «Малина-2» (образ 5.08 u43) — что там внутри и
куда встраивается наш агент. Разобрано из образа `tools/ext4extract.py`;
сами файлы прошивки в репозиторий не кладём, это чужой код.

## Система

| | |
|---|---|
| ОС | Raspbian 8 «jessie», ядро Linux, systemd |
| Корень | `/dev/mmcblk0p2`, монтируется **только для чтения** |
| Настройки | `/dev/mmcblk0p3` → `/settings`, **на запись**, переживает обновления |
| Вебморда | `/var/www/html` → симлинк на `/settings/html` |
| SSH | `openssh-server` установлен и включён (`S02ssh`), пользователь `pi` |
| Есть | php5-cli, python, sqlite. Нет mosquitto — он и не нужен |

Ключевое следствие: **всё наше — и агент, и веб-страница, и настройки —
живёт на `/settings`**. Корень трогать не нужно, а обновление прошивки
записываемый раздел не стирает.

## Откуда берутся данные

`mapd`, `mpptd`, `batmond` общаются с железом по последовательному порту и
кладут **готовый JSON** в разделяемую память System V. Ровно эти же байты
`read_json.php` отдаёт по HTTP:

| Ключ | Размер | Что внутри |
|---|---|---|
| 2015 | 2048 | МАП: один JSON до маркера `#EOF` |
| 2016 | 4096 | КЭС: по 1024 байта на контроллер, каждый до `#EOF` |
| 2017 | 2048 | Батарея: `[0..1023]` minute_data, `[1024..]` second_data |
| 2018 | 1024 | Зарядное |
| 1996 | 2048 | EEPROM МАП (настройки, не телеметрия) |
| 5000 | 1024 | Байты состояния служб: 0 — mapd, 1 — mpptd, 5 — charger, 6 — emoncms |

Читать нужно с `S_IRUSR` — только на чтение, как это делают их собственные
скрипты. Последовательный порт занят `mapd`, лезть туда нельзя и незачем.

**Разбирать ничего не надо**: в сегментах лежит тот же JSON, что мы уже
разбираем в `internal/microart`. Протокол МикроАрт для чтения телеметрии не
требуется — он нужен только для записи в ячейки, а мы не пишем.

## Как живут демоны

Их супервизор `scd.pl` раз в 10 секунд смотрит, что должно работать, и
поднимает упавшее: `/usr/sbin/mapd`, `/usr/sbin/emoncmsd` и так далее.

Включение и выключение из вебморды сделано флаг-файлами:

```php
// emoncms_switch.php
file_exists('/var/map/emoncmsd')                    // работает ли
shell_exec('sudo touch /var/map/emoncmsd');         // включить
shell_exec('sudo touch /settings/sos/emoncmsd');    //   и стартовать при загрузке
shell_exec('sudo /usr/sbin/emoncmsd');
shell_exec('sudo kill -sigterm `pidof -x emoncmsd`'); // выключить
```

Настройки — JSON-файл в `/settings/web-data/`, демон перечитывает его по
`SIGUSR1`, который шлёт страница после сохранения. Состояние отправки демон
кладёт байтом в сегмент 5000, вебморда рисует по нему зелёный или красный
значок.

`emoncmsd.pl` — готовый образец всего этого: читает shm, берёт настройки из
`/settings/web-data/emoncms.json`, шлёт наружу, отчитывается о результате.
Наш агент повторяет ту же схему, только вместо HTTP-запроса в облако —
публикация в MQTT.

## Куда что кладётся

```
/settings/daemons/microart-mqttd     агент (статический бинарник Go)
/usr/sbin/microart-mqttd             симлинк, как у их демонов
/settings/web-data/mqtt.json         настройки, пишет веб-страница
/settings/html/mqtt.php              страница «MQTT» в их вебморде
/settings/html/mqtt_switch.php       включить/выключить агента
/settings/html/get_mqtt_*.php        состояние и настройки для страницы
/settings/sos/microart-mqttd         флаг автозапуска
/var/map/microart-mqttd              флаг «включён»
```

Пункт меню добавляется в `/settings/html/load_menu.php`. Он на записываемом
разделе, но при обновлении прошивки может быть заменён — установщик должен
уметь дописать пункт заново, как это делает `install.sh` со вкладкой MimiSetup.

## Частота опроса

Читать shm практически бесплатно: ни PHP, ни HTTP, ни обращения к железу.
Ограничение только в том, как часто данные там обновляются:

| Источник | Обновляется |
|---|---|
| `bat` second_data | раз в секунду |
| `bat` minute_data | раз в минуту |
| МАП | по мере обмена с устройством, порядка секунды |
| Усреднение в их базе | 5 секунд |
| Их менеджер событий | проверяет значения раз в 2–3 секунды |

Разумный шаг агента — **1 секунда**, и это уже предел полезного: чаще в
сегментах просто не появляется новых данных. Для сравнения, через HTTP-API
быстрее 5 секунд ходить не стоит — каждый запрос поднимает PHP.

В брокер при этом уходит только изменившееся, поэтому секундный опрос не
означает секундного потока сообщений: заряд батареи меняется раз в минуты,
и его топик столько же и молчит.

## Сборка под устройство

Raspberry Pi 2/3 — ARMv7, `GOARM=7`. Для Pi 1 и Zero нужен `GOARM=6`.
CGO не нужен, бинарник статический, зависимостей на устройстве не требует.
