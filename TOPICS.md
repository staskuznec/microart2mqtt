# Топики MQTT

Агент на «Малине» (и центральный демон) публикует **всё**, что отдаёт инвертор.
Топики создаются автоматически из полей API — вручную ничего описывать не нужно.

Ниже — как устроены имена, что в значениях и какие поля обычно нужны.

## Корень

Всё висит под корнем из настроек — по умолчанию `microart/inv1`. У каждого
инвертора он свой (`microart/inv1`, `microart/inv2`, …), чтобы топики не
пересекались. Дальше в примерах корень — `microart/inv1`.

## Структура

```
microart/inv1/availability            online | offline
microart/inv1/map                     {…весь JSON раздела МАП…}
microart/inv1/map/<поле>              одно значение
microart/inv1/bat                     [{…minute…},{…second…}]  (весь JSON)
microart/inv1/bat/0/<поле>            данные минутные   (обновляются раз в минуту)
microart/inv1/bat/1/<поле>            данные секундные  (обновляются раз в секунду)
microart/inv1/mppt                    [{…},{…}]  (весь JSON контроллеров)
microart/inv1/mppt/<n>/<поле>         контроллер КЭС №n (с 0)
```

Разделы соответствуют запросам API малины (`read_json.php?device=…`):

| Раздел | Что это | Источник |
|--------|---------|----------|
| `map`  | состояние МАП: сеть, нагрузка, выход, статусы | `device=map` |
| `bat`  | батарейный монитор: `0` — минутные, `1` — секундные данные | `device=bat` |
| `mppt` | солнечные контроллеры (КЭС), по одному объекту на контроллер | `device=mppt` |

Раздел `bat` — массив из двух объектов, поэтому индекс `0`/`1` в пути. Раздел
`mppt` — массив контроллеров, индекс `0..3`. Раздел `map` — один объект, индекса
нет. Имена полей внутри — как в протоколе МикроАrt (с ведущим `_` у части полей).

Кроме плоских значений в `…/map/<поле>` агент кладёт и **весь JSON раздела** в
`…/map`, `…/bat`, `…/mppt` — для тех, кто хочет разобрать ответ целиком.

## Значения

- Публикуются **строкой, как отдаёт малина**: число приходит как `"231.0"`,
  `"88.0"`, `"-12.5"`; флаги — как `"0"`/`"1"`; режим — текстом. Тип не
  навязывается — подписчик приводит сам (в Home Assistant это `value_template`).
- **retain** включён по умолчанию: подписчик, подключившийся позже, сразу
  получает последние значения, а не ждёт следующего опроса.
- В брокер уходит только **изменившееся** значение. Раз в `republish_sec`
  (по умолчанию 10 минут) публикуется весь набор заново — на случай, если
  подписчик или брокер потеряли состояние. Поэтому редкий топик (заряд АКБ)
  и молчит подолгу — это нормально.
- **QoS** — из настроек (по умолчанию 0).

## Доступность

- `microart/inv1/availability` = `online`, пока инвертор отвечает и данные идут.
- `offline` — если малина перестала отвечать, агент выключили в вебе или он
  штатно остановлен. Значение `offline` также стоит завещанием (LWT): если
  агент/связь пропадут внезапно, брокер сам разошлёт `offline`.

## Часто нужные поля

Полный список зависит от модели МАП; надёжнее всего посмотреть его в топике
`microart/inv1/map` (и `…/bat`, `…/mppt`) — там весь JSON с текущими значениями.
Вот что обычно берут:

| Топик | Что это | Единицы |
|-------|---------|---------|
| `bat/0/C_100_remain` | заряд АКБ | % |
| `bat/0/Uacc_avg`     | напряжение АКБ (среднее за минуту) | В |
| `bat/0/Iavg`         | ток АКБ (средний), знак = заряд/разряд | А |
| `bat/0/C_Ah_remain`  | остаточная ёмкость | А·ч |
| `bat/0/mppt_day_E`   | выработка солнца за день | Вт·ч |
| `bat/1/Sun_P`        | мгновенная мощность от контроллеров | Вт |
| `bat/1/t_bat`        | температура АКБ | °C |
| `map/_UNET`          | напряжение сети | В |
| `map/_PNET`          | мощность по сети (со знаком: продажа) | Вт |
| `map/_PLoad`         | мощность нагрузки | Вт |
| `map/_Status_Char`   | статус работы МАП | код |
| `map/_MODE`          | режим | текст |
| `mppt/0/P_PV`        | мощность панелей контроллера 0 | Вт |
| `mppt/0/V_Bat`       | напряжение на АКБ по данным контроллера | В |

Названия и набор полей — из документации МикроАrt (`docs/malina2.pdf`, раздел
про `read_json.php`). Значения на шине ровно те же, что в этих ответах API.

## Как посмотреть, что публикуется

```sh
# всё дерево инвертора
mosquitto_sub -h <брокер> -v -t 'microart/inv1/#'

# только доступность и заряд
mosquitto_sub -h <брокер> -v -t 'microart/inv1/availability' -t 'microart/inv1/bat/0/C_100_remain'

# все инверторы разом
mosquitto_sub -h <брокер> -v -t 'microart/#'
```

## Пример для Home Assistant

```yaml
mqtt:
  sensor:
    - name: "Инвертор 1 — заряд АКБ"
      state_topic: "microart/inv1/bat/0/C_100_remain"
      unit_of_measurement: "%"
      device_class: battery
      availability_topic: "microart/inv1/availability"
    - name: "Инвертор 1 — напряжение сети"
      state_topic: "microart/inv1/map/_UNET"
      unit_of_measurement: "V"
      device_class: voltage
      availability_topic: "microart/inv1/availability"
```
